# المستخدمون والصلاحيات وتأجيل الدفع

تحديث 2026-09-09 بطلب المستخدم. هذا الملف يكمل خطة 2.0 ويتقدم على الأوصاف السابقة عند التعارض في الصلاحيات وترتيب الدفع. نُفذ أساس الحسابات والجلسات والصلاحيات والتحقق الثنائي في المرحلة 03؛ أدوات الإدارة والتعليق التفصيلية تتبع في مرحلتي القوالب والمناسبات.

## الأدوار في النسخة الأولى

ثلاث فئات استخدام: ضيف بلا حساب، عميل مسجل، مدير منصة. الأدوار المخزنة اثنان فقط customer وadmin؛ الضيف ليس سجلاً أو دوراً في users. لا نضيف محرر أدوار وصلاحيات ديناميكي أو فرق عمل الآن؛ الصلاحيات معرفة في Policies/Gates وقابلة للتوسعة لاحقاً.

| العملية | الضيف | العميل | المدير |
|---|---|---|---|
| تصفح القوالب ومعاينتها | نعم | نعم | نعم |
| إنشاء مناسبة وتعديل تصميم | لا | مناسباته فقط | مناسباته فقط؛ لا تعديل مسودات العملاء |
| قراءة تصميم خاص/أصول أصلية | لا | ضمن ملكيته واستحقاقه | لا تجاوز تلقائي لصلاحيات العميل |
| فتح دعوة عامة وRSVP | منشورة وصالحة فقط | الشروط نفسها | الشروط نفسها |
| قائمة الضيوف والهواتف والملاحظات | لا | صاحب المناسبة فقط | غير متاحة افتراضياً |
| بيانات الحساب والجلسات | لا | حسابه فقط | إدارة الحالة وبيانات تشغيل محدودة؛ لا كلمات مرور |
| إدارة القوالب والأصول والمجموعات | لا | لا | نعم |
| تعليق حساب أو إعادة تفعيله | لا | لا | نعم، مع سبب وسجل |
| مراجعة حالة المناسبات ومهام التصيير | لا | مناسباته | معلومات تشغيلية؛ لا JSON خاص |
| تعليق رابط مخالف أو إعادة إتاحته | لا | لا | نعم، مع سبب؛ الإتاحة لا تتجاوز الدفع أو الانتهاء |
| تغيير is_paid أو تفعيل مجاني | لا | لا | لا؛ الدفع الموثق هو المصدر |
| مراجعة الطلبات المالية | لا | طلباته | قراءة تشغيلية محدودة بعد مرحلة الدفع |
| ترقية مستخدم إلى مدير | لا | لا | عبر إجراء تشغيلي موثوق خارج واجهة المستخدم في النسخة الأولى |

المدير ليس superuser يتجاوز كل Policy. إذا أنشأ مناسبة خاصة به تطبق عليه قواعد العميل والدفع نفسها. دور الدعم أو مدير المحتوى المستقل وصلاحيات الفرق مؤجلة حتى توجد حاجة فعلية.

## الحسابات والجلسات

تسجيل ودخول وخروج، تحقق بريد، نسيان/إعادة تعيين كلمة مرور، تعديل الاسم والهاتف، تغيير كلمة المرور، وإدارة الجلسات/الخروج من الأجهزة الأخرى. تغيير البريد يعيد التحقق. يسمح بإنشاء المسودة قبل التحقق؛ النشر وتحديث المنشور يتطلبان بريداً متحققاً. التحقق بخطوتين مطلوب للمدير قبل الوصول إلى إدارة الإنتاج، مع أكواد استرداد مخزنة بأمان وتأكيد كلمة المرور للعمليات الحساسة.

التسجيل ينشئ customer وactive حصراً؛ role وstatus لا يأتيان من النموذج. تعيين المدير الأول عبر أمر تشغيل موثوق دون كلمة مرور ثابتة في seeder. حماية الدخول والاسترداد من المحاولات المتكررة، عدم كشف وجود البريد برسائل الاسترداد، تدوير session عند الدخول، وإبطال الجلسات عند التعليق وإعادة التحقق من حالة الحساب في كل طلب.

## تغييرات البيانات

users: إضافة role VARCHAR(20) بقيم customer/admin وافتراضي customer، status VARCHAR(20) بقيم active/suspended وافتراضي active، suspended_at DATETIME(6) NULL، suspension_reason VARCHAR(500) NULL. فهرس(role,status). حقول المصادقة الثنائية يحددها التنفيذ المختار، مع تشفير السر وأكواد الاسترداد وعدم إرسالها في props العادية.

events: إضافة suspended_at DATETIME(6) NULL وsuspension_reason VARCHAR(500) NULL. يبقى status التجاري draft/published/expired؛ التعليق منفصل ولا يحوّل المسودة إلى منشورة ولا يغير is_paid.

إضافة جدول audit_logs ليصبح مجموع جداول الأعمال 13، مع بقاء جداول Laravel التشغيلية منفصلة:

| الحقل | النوع والقيد |
|---|---|
| id | BIGINT UNSIGNED PK |
| actor_id | BIGINT UNSIGNED FK users NULL للعمليات النظامية، RESTRICT |
| actor_type | VARCHAR(20): user/system |
| action | VARCHAR(100) من قائمة معروفة |
| subject_type | VARCHAR(40) من قائمة معروفة |
| subject_id | BIGINT UNSIGNED؛ معرف المورد؛ polymorphic بلا FK عام |
| reason | VARCHAR(500) NULL |
| metadata | JSON NULL؛ مفاتيح تشغيلية مسموحة فقط |
| created_at | DATETIME(6) UTC |

فهارس(actor_id,created_at) و(subject_type,subject_id,created_at). لا updated_at ولا واجهة تعديل/حذف للسجل. العمليات الإدارية تسجل الحدث داخل transaction التغيير نفسه. لا تحفظ كلمات مرور أو tokens أو design_json أو محتوى RSVP في سجل التدقيق. سجل التطبيق append-only وليس ادعاء بأنه محصن ضد مدير قاعدة البيانات؛ سياسة الاحتفاظ لم تحسم بعد.

## تعليق الحساب والرابط

تعليق المستخدم يمنع جلساته وطلباته الجديدة، ويمنع عرض دعواته وRSVP وتسليم أصولها أثناء التعليق. يعرض للضيف إشعار عدم إتاحة عام بلا كشف سبب داخلي. لا يمسح البيانات ولا يغير سجل الدفع. إلغاء التعليق يعيد الوصول فقط إذا كان الحساب نشطاً والدعوة منشورة ومدفوعة وغير منتهية وغير معلقة مستقلاً. التحقق يشمل مسارات الأصول وcache، لا الصفحة وحدها.

تعليق دعوة بعينها يمنعها دون تعطيل حساب صاحبها. يحظر تعليق آخر مدير نشط أو تعليق المدير لنفسه عبر هذه الواجهة، وتطبق العملية بقفل ومعاملة تمنع سباق تعليق جميع المديرين.

## لوحة الإدارة المحدودة

تدخل النسخة الأولى لوحة تشغيل صغيرة: مستخدمون وحالاتهم، قوالب وأصول ومجموعات، حالات مناسبات دون فتح المسودات الخاصة، مهام تصيير فاشلة وإعادة محاولتها، وسجل إجراءات إدارية. صفحة الطلبات تضاف مع الدفع أخيراً. لا انتحال حساب عميل ولا قراءة قوائم ضيوفه. ترقية الأدوار، محرر صلاحيات، تحليلات متقدمة واسترجاع مالي يدوي ليست ضمن اللوحة الحالية.

توزيع الملفات: Users/Actions وDTOs وPolicies وModels للحسابات، ومكونات الإدارة داخل Domains المعنية. Http/Controllers/App/Admin وPages/App/Admin للعرض فقط. خدمة AuditLogger مستقلة ومستخدمة في Actions؛ حماية المسارات وActions والموارد مباشرة، لا الاعتماد على إخفاء زر React.

## الدفع آخر مرحلة برمجية

ترتيب المراحل: 01–10 كما هي مع إضافة الحسابات والصلاحيات؛ 11 النطاقات والضيف؛ 12 RSVP؛ 13 الانتهاء والتشغيل؛ 14 الدفع؛ 15 الاختبار النهائي والإطلاق.

نؤسس جداول الدفع وعقد الاستحقاق من البداية حتى لا تعاد كتابة المعمارية، لكن ربط Gateway وCheckout وWebhooks والتسوية ينفذ في المرحلة 14 فقط. تراقب webhooks فعلياً بعد إضافتها في تلك المرحلة.

قبلها تختبر حالات draft/paid/published/expired باستخدام factories وfixtures في اختبار/تطوير معزولين فقط. لا route عام أو زر مدير لتجاوز الدفع، ولا مفتاح production يسمح بالتفعيل التجريبي. لا يرسل العميل is_paid. بيئة الإنتاج تبقى مغلقة عن النشر المدفوع حتى اكتمال التكامل؛ fixtures لا تشحن إليها. إعادة تجربة نشر مدفوع في الاختبارات لا تعني منح نشر مجاني للعملاء.

## معايير القبول

- عميل لا يقرأ أو يعدل مناسبة عميل آخر حتى عند تغيير ID مباشرة.
- إرسال role=admin أو status=active أو is_paid=true لا يرفع الصلاحية.
- مدير لا يقرأ RSVP خاصاً أو JSON مسودة لمجرد دوره.
- كل تعليق وإعادة تفعيل وتغيير أصل يسجل مع الفاعل والسبب عند لزومه.
- تعليق الحساب يلغي الجلسات ويغلق الدعوات والأصول؛ فكه لا يفتح دعوة منتهية.
- وظائف إدارة الإنتاج تتطلب المصادقة الثنائية، وحماية آخر مدير تختبر بالتزامن.
- جميع عمليات النشر تتحقق من الدفع على الخادم، ولا يوجد منفذ تفعيل اختباري في الإنتاج.
