# خطة التنفيذ خطوة بخطوة

كل الخطوات أدناه مخططة وغير منفذة. يبدأ كل جزء بعد إكمال متطلباته السابقة، مع تسليم كود كامل لذلك الجزء.

| الخطوة | العمل والتسليم | معيار القبول |
|---|---|---|
| 1 | تثبيت قرارات الإصدار في 08-decisions | اعتماد الاستثناءات والتسعير المطلوب قبل الدفع الحقيقي |
| 2 | إنشاء Laravel 12 + React 19 + Inertia v2 + TS strict وFabric v6 | بناء ناجح، versions مثبتة في lockfiles، اتصال MySQL |
| 3 | تأسيس Domains وInfrastructure وauth | دخول/خروج وCSRF؛ cookie معزول؛ سياسة ملكية فعالة |
| 4 | migrations للجداول العشرة، models، enums، DTOs، factories | migrate وrollback على قاعدة اختبار MySQL؛ FK وUNIQUE وCHECK تعمل |
| 5 | seed قوالب وأصول مرخصة | قالب زفاف وتخرج صالحان مع preview وأصول خاصة |
| 6 | CreateEventAction وExpirationCalculator وslug | إنشاء مناسبة وتصميم ذرياً، slug متزامن بلا تكرار |
| 7 | الصفحات الأساسية ولوحة المناسبات | المستخدم لا يرى مناسبات غيره؛ حالات فارغة وخطأ |
| 8 | Canvas adapter وuseCanvas والطبقات والأدوات | نصوص عربية وأصول، تنظيف listeners، معاينة منخفضة الدقة بعلامة |
| 9 | SaveDesignAction وحفظ تلقائي وrevision | رفض JSON غير آمن؛ تبويبان لا يكتبان فوق بعض بصمت |
| 10 | design_renders ومصدر Canvas | preview صحيح؛ إعادة محاولة؛ لا تصدير نهائي لغير المدفوع |
| 11 | Gateway واحد sandbox وCheckout وWebhooks | تحقق توقيع ومبلغ/عملة، duplicate وآثار متأخرة بلا نشر خاطئ |
| 12 | ProcessPaymentAction وPublishEventAction | دفع مثبت ثم نشر وتجهيز؛ استرداد مهام ضائعة بعد restart |
| 13 | نطاقات فرعية وMiddleware وتسليم محمي | wildcard DNS/TLS؛ draft غير متاح؛ انتهى الوقت يوقف الوصول فوراً |
| 14 | RSVP ولوحة الحضور | تحقق وتحديد معدل ومنع إعادة الإرسال نفسه وحساب مرافقين صحيح |
| 15 | ExpireEventsCommand وجدول التشغيل | أمر يومي قابل للإعادة؛ التطبيق يمنع الوصول حتى لو توقف scheduler |
| 16 | مراجعة شاملة وإطلاق تجريبي | سيناريو كامل، queue شغالة، backup واستعادة، مراقبة فشل الدفع/التصيير |

## اختبارات القبول الحرجة

- إنشاء مناسبة زمنها محلي ينتج expires_at بعد عشرة أيام تقويمية؛ الاختبار يشمل تغيير التوقيت الصيفي وحد المساواة.
- لا تعديل في user_id أو status أو is_paid من client؛ مستخدم B لا يقرأ تصميم أو RSVP مستخدم A.
- حفظ متزامن: واحد ينجح، الآخر يتلقى تعارضاً مفهوماً مع بقاء النص المحلي.
- Webhook مكرر ومتزامن يسبب تسوية واحدة؛ إشعار فشل متأخر لا يرجع completed.
- mismatch مبلغ/عملة/بيئة/طلب يرفض النشر. انقطاع إنشاء Checkout يعاد بالمفتاح نفسه.
- قتل worker بعد تثبيت الدفع وقبل dispatch لا يفقد التصيير؛ lease المنتهي يعاد التقاطه.
- تصيير قديم ينتهي بعد نسخة أحدث لا يطغى عليها. انتهاء أثناء التصيير لا يفتح الرابط.
- زيارة الرابط عند expires_at أو بعده، وإرسال RSVP وتسليم الصورة، كلها تتوقف دون انتظار Cron.
- double click في RSVP لا يضاعف العدد؛ هاتف واحد/اسم واحد لا يثبت هوية ولا يمنع ضيفاً آخر.
- لا أصل عالي الدقة في Network أو Inertia props لمستخدم غير مدفوع. renderer يرفض مصادر شبكة عشوائية.
- المحرر والتصدير يطابقان ترتيب الطبقات والخط العربي والإحداثيات؛ مراجعة فعلية على الهاتف وسطح المكتب.

## متطلبات التشغيل

نطاق رئيسي ونطاق ضيوف مضبوطان في config، wildcard DNS وشهادة TLS، private object storage، worker دائم، scheduler، أسرار بوابة لكل بيئة، logging بمعرفات الطلبات دون PII غير ضروري، حدود upload/render، نسخ احتياطي مجرب. مراقبة طول الطابور وwebhooks العالقة وrender failures وفشل scheduler. لا يبدأ دفع إنتاجي قبل تسوية السياسات المفتوحة.
