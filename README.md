# Methaq

منصة ميثاق لإنشاء وتخصيص الدعوات الرقمية.

## المتطلبات

- PHP `>=8.4.1` و`<9.0` للاعتماديات المقفلة حالياً: يحدد `composer.json` و`composer.lock` قيد المشروع `^8.3`، لكن الحزم المقفلة من Symfony 8.1 تتطلب `>=8.4.1`. اجتاز PHP 8.4.1 المثبت محلياً `composer check-platform-reqs`؛ كما يؤكد `composer prohibits php 8.4.0 --locked` أن 8.4.0 لا يفي بمتطلبات الحزم المقفلة. عند تحديث الاعتماديات، أعد التحقق من الحد الأدنى.
- Composer 2. يتطلب تشغيل migrations واختبارات MySQL اتصالاً بقاعدة MySQL.
- React 19 وInertia.js v2 وTypeScript وFabric.js v6؛ الإصدارات المقفلة موضحة في `package.json` و`package-lock.json`.
- [الخطة المعتمدة](requirements/09-methaq-master-plan-v2.md) و[قائمة التنفيذ](requirements/10-execution-checklist.md).

## إعداد تثبيت جديد

```sh
composer install
if [ ! -f .env ]; then cp .env.example .env; fi
if grep -q '^APP_KEY=$' .env; then php artisan key:generate; fi
php artisan migrate
php artisan db:seed
php artisan serve
```

يضبط الأمر الشرطي ملف `.env` فقط إن لم يكن موجوداً، ويولّد `APP_KEY` فقط عندما يكون فارغاً. راجع إعدادات `.env` واضبط اتصال MySQL قبل `php artisan migrate`. تستخدم `.env.example` قاعدة MySQL باسم `methaq` والجلسات وcache وqueue عبر قاعدة البيانات؛ تحتاج قاعدة جديدة إلى migrations المناسبة لهذه الجداول. يملأ `php artisan db:seed` مكتبة القوالب وأصولها (الخطوط والإطارات والخلفيات والموسيقى)، ويمكن إعادة تشغيله دون تكرار السجلات. صفحة ميثاق متاحة افتراضياً على `http://localhost:8000`.

## تشغيل تثبيت موجود

احتفظ بملف `.env` و`APP_KEY` الحاليين. لا تنسخ `.env.example` فوق إعداد موجود ولا تشغّل `php artisan key:generate` على تثبيت ذي مفتاح مضبوط؛ تغيير المفتاح قد يبطل البيانات المشفرة والجلسات والكوكيز. بعد تحديث المصدر، استخدم `composer install` و`npm ci` عند الحاجة، ثم شغّل Laravel وVite في نافذتي طرفية منفصلتين:

```sh
php artisan serve
npm run dev
```

قبل تطبيق تغييرات قاعدة البيانات على تثبيت موجود، راجع حالة migrations:

```sh
php artisan migrate:status
```

شغّل `php artisan migrate` فقط عندما تتطلب التغييرات المراجعة ذلك.

## الاختبارات

اختبارات Laravel تحتاج MySQL؛ عند تشغيلها على SQLite الافتراضية تتخطى نفسها. أنشئ قاعدة الاختبار `methaq_schema_test` كما في [سجل قاعدة البيانات](requirements/12-database-implementation.md)، ثم:

```sh
php artisan test -c phpunit.mysql.xml --compact
composer validate --strict
```

اختبار إعادة التحقق من البريد يتخطى نفسه عمداً، لأن التحقق من البريد معطّل مؤقتاً (راجع [سجل القرارات](requirements/08-decisions.md)).

## البنية الحالية

يعتمد التطبيق Modular DDD مع حدود المجالات التالية في `app/Domains` و`resources/js/Domains`:

- `Events`: إنشاء المناسبات وبياناتها وملكيتها.
- `Editor`: مكتبة القوالب والأصول، عقد التصميم، محرر البطاقة ومشهد الدعوة.
- `Payments`: توجد نماذج `Order` و`PaymentWebhook` وEnums؛ تكامل بوابة الدفع ومعالجة الدفع الفعلية غير منفذين.
- `RSVP`: استقبال ردود الضيوف.
- `Users`: الحسابات والصلاحيات وسجل التدقيق.

المجالات غير متساوية في اكتمالها؛ أسماء المجلدات تصف حدود المسؤولية ولا تعني أن كل الميزات المخطط لها مكتملة. تنظم `app/Http/Controllers` محولات HTTP حسب `Web` و`App` و`Admin` و`Guest`، وتحتوي `resources/js/Pages` صفحات Inertia، بينما تضم `resources/js/Types` عقود TypeScript المشتركة.

ضمن `Editor`، تتبع ملفات PHP مجلدات متخصصة مثل `Actions` و`DTOs` و`Enums` و`Models` و`Policies` و`Services`. وفي الواجهة، تفصل `Components` و`Hooks` عن خدمات المجال. **يبقى `resources/js/Domains/Editor/Services` بهيكله الحالي؛ لم تُنقل ملفاته أو تُعد تسميتها.**

## المسارات والوظائف الموجودة

يجمع `routes/web.php` وحدات المسارات، مع تسجيل مسارات المصادقة من Fortify:

- `routes/public.php`: `GET /` (`Web/Home`)، و`GET /templates` (`Web/Templates`)، و`GET /about` (`Web/About`)، و`GET /contact` (`Web/Contact`)، و`GET /privacy` (`Web/Privacy`).
- `routes/app.php`: مجموعة `/app` المحمية بـ`auth` و`active`، وتشمل لوحة المستخدم، إنشاء المناسبة، عرضها، محرر التصميم، العرض التقديمي، الملف الشخصي، ومسودة اقتراح Ivory.
- `PATCH /app/events/{event}/design` لحفظ وثيقة التصميم؛ يستخدم مسار حفظ مع مراجعة للتصميم.
- `routes/admin.php`: مجموعة الإدارة تحت `/app/admin` داخل مجموعة التطبيق، وتُحمى أيضاً بـ`admin.2fa` التي تتحقق من دور المدير وتفعيل المصادقة الثنائية.
- `routes/guest.php`: على نطاقات الدعوات الفرعية، يسمح `ResolvePublishedEvent` بتحميل دعوة منشورة غير منتهية؛ ويضم المسار عرض الدعوة وإرسال RSVP.
- `GET /dev/design-lab` متاح فقط في بيئتي `local` و`testing` عبر `LocalDevelopmentOnly`.
- **انتهاء الدعوات:** رابط الضيف يبقى مفتوحاً يوم المناسبة ومدة `METHAQ_INVITATION_GRACE_DAYS` (القيمة الافتراضية يومان) بتوقيت `METHAQ_INVITATION_TIMEZONE` (طرابلس). بعدها يرجع الخادم صفحة «انتهت صلاحية هذه الدعوة» بحالة 410، ويرفض تأكيد الحضور. الأمر اليومي `methaq:expire-invitations` يحدّث الحالة في لوحة التحكم فقط، ويحتاج Cron: `* * * * * php artisan schedule:run`.
- `/admin`: لوحة إدارة Filament 5، بتسجيل الدخول نفسه، للمدير النشط مع المصادقة الثنائية فقط. لوحة React القديمة `/app/admin` باقية احتياطاً.

تتضمن الشيفرة واجهات Inertia للمصادقة والحسابات، وإدارة المناسبات، ومحرر البطاقة والمشهد، ومكتبة الإدارة، ودعوة الضيف وRSVP. وجود نماذج الدفع أو مسارات الدفع في الخطط لا يعني وجود معالجة دفع جاهزة: لا توجد حالياً مسارات checkout أو webhook في `routes/web.php` ولا تنفيذ مزود دفع في `app/Domains/Payments`.

تفاصيل المخطط وتشغيل اختبارات MySQL موثقة في [سجل قاعدة البيانات](requirements/12-database-implementation.md).

## الموقع العام ونظام التصميم

واجهات الموقع العام موجودة في `resources/js/Pages/Web`: تستخدم Home وAbout وContact وTemplates غلاف `PublicLayout` القابل للوصول باتجاه RTL، والذي يجمع Navbar المتجاوب وmain وFooter الموحد. يعرض Navbar المسار النشط وحالة الحساب، ويحتوي Footer روابط الموقع والرسالة التعريفية وحقوق السنة الحالية.

يعتمد المشروع Tailwind CSS v4 عبر `@tailwindcss/vite`، وصفحات الموقع العام مكتوبة بأصناف Tailwind فقط. يستورد `app.css` هوية الخطوط والمتغيرات الأساسية من `brand.css`، ثم ثيم Editorial Serenity العام من `public-theme.css`: بألوان `home.html` في مرجع Stitch: الأخضر الزيتوني `#203322` للأساس، والبرونزي `#7a613b` وتدرجاته للتفاصيل، وخلفية الصفحة `#f6fbf2` وطبقاتها، ودرجات النص والحدود. الشريط العلوي ثابت بعناوين المرجع، والخطوط كما في المرجع بالضبط: Noto Sans Arabic للنص، وAmiri بوزن 700 للعناوين، وManrope للاتيني، كلها محلية، مع حالات تركيز موحّدة.

المرجع البصري تصدير Stitch في `requirements/design-reference/editorial-serenity/`؛ اقرأ `README.md` فيه أولاً، فهو مرجع للشكل وليس كوداً للنسخ. قسم «قوالب مختارة من ميثاق» يعرض فقط القوالب التي يختارها المدير من مكتبة الإدارة («عرض في الرئيسية»). الحركة في الصفحات العامة بمكوّن `Reveal` وبمتغيرات `--animate-methaq-*`، وتتوقف مع «تقليل الحركة». أقسام الصفحة الرئيسية في `resources/js/Components/Public/Home/` بنفس ترتيب المرجع: الواجهة مع عرض الظرف التلقائي، القوالب المميزة، الخطوات، تجربة الظرف اليدوية، المزايا، والخاتمة. النصوص والأسماء والمدن ليبية، والأرقام والتواريخ بالأرقام الغربية (14/8/2027).

## دعوة الضيف: الظرف والمشهد

- **ظرف واحد:** `InvitationEnvelope` و`InvitationSeal` في `resources/js/Domains/Editor/Components`، وتنسيقهما في `resources/css/envelope.css`. يستدعيهما المحرر (معاينة أشكال الظرف والختم) ومشغّل الضيف وثيمات المشهد وعرض الصفحة الرئيسية، فما تختاره صاحبة المناسبة هو ما يراه الضيف. لا تكتب ظرفاً جديداً؛ أضف شكلاً جديداً للظرف الموحّد.
- **الختم:** شعار ميثاق داخله ثابت، ويتغيّر شكل الختم ولونه فقط. حقل `monogram` موجود في البيانات ولا يُعرض.
- **الحركة:** CSS transitions فقط عبر `data-state` (`closed` ← `open` ← `presenting`)، وتنعكس للإغلاق تلقائياً. لا يستخدم المشروع GSAP. كل الحركات تحترم «تقليل الحركة» في جهاز الزائر.
- **خلفيات المشهد:** طبقة ذرات ولمعات عند اللمس (`InvitationAmbience`) لكل الخلفيات. خلفية `henna-noir` تحوّل المشغّل إلى `NoirInvitationScene` بدخان عنابي متحرك (WebGL مع بديل 2D).
- **القوالب:** تسعة قوالب قابلة للتعديل في المكتبة، منها «ليلة عنابية» (حنّة) بموسيقاه وخطوطه، وأربع باقات بثيماتها: «ياسمين أبيض» و«زرقة المتوسط» و«تراب غدامس» و«لافندر وفضة». كل باقة = قالب + إطار + زاوية + فاصل + ميدالية، مربوطة بالقالب فتظهر «مقترح» في المحرر، ومجموعة جاهزة تُضاف بضغطة. القوالب تُبنى في `TemplateDesignFactory` وتُزرع بـ`TemplateLibrarySeeder`.
- **ترخيص الأصول:** مصدر كل أصل وترخيصه موثّق بجانبه (`sources.json` و`public/brand/fonts/SOURCES.txt`). المشاريع المرجعية خارج ميثاق للقراءة فقط، ولا تُنسخ منها بيانات شخصية.

نشر نسخة الدعوة للضيوف (المرحلة 10) لم يُنفّذ بعد؛ صفحة الضيف تقرأ النسخة المنشورة، وتعرض الثيمات تلقائياً عند تنفيذ النشر. المعاينة متاحة الآن لصاحبة المناسبة من صفحة «الظرف والفتح» (`/app/events/{id}/presentation`).

## توصيات مستقبلية اختيارية

هذه أفكار تنظيمية وليست تغييرات منفذة أو متطلبات حالية. إذا زادت مسؤوليات خدمات المحرر، يمكن في عمل مستقبلي مستقل دراسة تجميع اتصال HTTP ومحولات Fabric/العرض في وحدات فرعية مع المحافظة على حدود `Editor` والعقود الحالية. لا يتطلب ذلك تغيير بنية `Editor/Services` الحالية، وأي نقل أو إعادة تسمية يحتاج مراجعة مستقلة للاستخدامات والاختبارات وموافقة منفصلة.
